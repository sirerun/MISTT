# Release and deferred local validation

The installed desktop app reads owner-owned, restricted `~/Library/Application Support/MISTT/config.json` before starting its relay. `MISTT_CONFIG` can select another restricted file. Configuration uses the documented Go environment keys and stores a token-file path, never token contents. To provision a new file later, use `python3 release/configure.py --endpoint wss://YOUR_QUALIFIED_ENDPOINT/mistt/v1/stream --token-file /absolute/restricted/token-file`. The provisioner defaults to the one vetted app-relative media helper selector; arbitrary helper paths are rejected. The helper creates with mode 0600 and refuses to replace existing configuration. Endpoint, helper ownership, permission grants and token validity still need real local qualification.

The source candidate is independent of actual build, native capture, model resource and installation qualification. Heavy commands below are intended for a later admitted run; importing the release module performs no build, network or signing action.

## Local validation

Run `bash release/local-validate.sh` with `MISTT_CLAIM_SCRIPT` pointing to the installed claim helper and `CLAIM_REMOTE` naming the shared Mac build-lease repository. The script checks load before every heavy command, holds the lease only for that command and keeps all caches/artifacts on the external SSD. Set `MISTT_RUN_RACE=1` for the sole race lane. The script does not launch capture or model workloads.

After source checks pass, native permissions, selected TikTok helper identity, simultaneous signals/exclusion, clocks/cutoff/closure and paired DGX real-time/headroom qualification remain required. Use the plan's acceptance tasks; synthetic fixtures do not satisfy these checks.

## Signed release

Sparkle is pinned to 2.10.0. Its official binary package checksum is `17e28312b8e18ab7cdbbe09a6fb28cc55a5479ec6c371dbc07cdecd2a14fd959`; the official tool archive checksum is `c2bf58aa8387266ac179357b1415d6f2635f044da8be41042af32425dae6da0c`.

`release.py build --version VERSION --build MONOTONIC_BUILD --output EXTERNAL_DIRECTORY` requires `MISTT_SIGN_IDENTITY` (Developer ID Application), `MISTT_SIGN_KEYCHAIN` (explicit existing signing keychain), `MISTT_SPARKLE_PUBLIC_KEY`, `MISTT_NOTARY_PROFILE`, `MISTT_SPARKLE_SIGN_TOOL`, `MISTT_SPARKLE_KEY_FILE` and `MISTT_RELEASE_REPOSITORY`. When distribution is in a separate public repository, set `MISTT_DISTRIBUTION_COMMIT_SHA` to an already-existing metadata commit there; same-repository compatibility defaults the distribution commit to source SHA. `MISTT_FEED_URL`, if supplied, must exactly equal the selected repository's canonical latest appcast URL. If the notarization profile uses a separate keychain, also set `MISTT_NOTARY_KEYCHAIN`. Obtain credentials through the owner's existing account/key ownership process; this code neither issues certificates nor creates keys.

Build only from the exact independently reviewed landed SHA, after required tests pass. On this Mac set `MISTT_CLAIM_SCRIPT` and `CLAIM_REMOTE`; the script checks uptime/load and acquires/releases the exact shared lease separately for each Go/Swift build command, before signing or network notarization. Do not hold a second outer lease around it. The script assembles arm64 app/relay/framework, sets the correct runpath and version, signs nested bundles, checks notarization acceptance, staples, reassesses Gatekeeper, signs archive/feed and writes real hash-bound cask metadata. Missing release credentials fail instead of producing an unsigned release.

`release.py publish --directory ARTIFACT_DIRECTORY` additionally requires `MISTT_TAP_REPOSITORY` and its scoped `MISTT_TAP_TOKEN`. Run from the accepted landed source. Before any tag, release or tap mutation, the helper verifies that the selected distribution repository is public and writable and that the exact distribution commit already exists and is reachable from its default branch. The version tag targets that public distribution metadata commit; private source remains recorded separately as `source_sha` provenance and is never pushed. An existing tag is accepted only when it identifies the same distribution commit. The embedded stable feed, appcast/archive URLs, manifest and cask must all name the selected distribution repository, so old signed artifacts cannot be relabeled. Publication verifies the archive against the app-embedded public key as well as real archive/feed signatures and reassesses the extracted app. It refuses an existing release or non-increasing build. Assets are staged as a draft, then exposed as a prerelease before updating the existing writable tap; only afterward is the stable release/latest feed promoted. Failed staging leaves the previous stable feed intact and preserves the new assets for explicit recovery. There is no cross-repository atomic transaction: publication evidence must check both targets before claiming completion. This helper never creates a tap, changes OAuth/billing, clobbers a tag or deletes another release.

The signed appcast is served at `https://github.com/DISTRIBUTION_REPOSITORY/releases/latest/download/appcast.xml`, embedded in the signed app and matched against manifest, appcast and cask URLs. `SURequireSignedFeed` is enabled. Installed automatic checks/downloads use Sparkle; installation waits for the correlated native/relay idle reservation and confirmed source closure. `MISTT_DISABLE_UPDATES=1` or the external `MISTTDisableAutomaticUpdates` defaults key disables automatic updates. Startup remains muted.

Required later evidence: signed A/B builds, actual cask audit/install, archive/feed/hash/Gatekeeper download checks, safe-idle deferral, genuine automatic A-to-B install/relaunch, permission continuity, rejected/interrupted update recovery and final locally installed running state. No release/deployment is executed by source authoring.

References: [Sparkle publishing](https://sparkle-project.org/documentation/publishing/), [pinned package](https://github.com/sparkle-project/Sparkle/blob/2.10.0/Package.swift), [updater delegate contract](https://github.com/sparkle-project/Sparkle/blob/2.10.0/Sparkle/SPUUpdaterDelegate.h).

## Explicit local cask operations

`python release/local_install.py` only inspects the requested cask/app. Select `install`, `launch`, `reinstall` or `uninstall` explicitly and supply the qualified Developer ID team with `--team-id`. Mutating modes reject a pre-existing app outside the requested cask, require real Developer ID/notary/Gatekeeper acceptance and use ordinary quit before replacement; no force kill, global package upgrade or configuration deletion is performed. These commands are prepared for later acceptance and were not run during coding.


## Recover an interrupted staged publication

Recovery is an explicit owner operation; `publish` deliberately refuses to replace an existing release. Do not delete or clobber tags, releases or uploaded assets to retry. Preserve the accepted local artifact directory and use the same exact source revision, version, build and keys.

1. Inspect the existing release with `gh release view vVERSION --repo DISTRIBUTION_REPOSITORY --json isDraft,isPrerelease,tagName,assets` and its tag with `gh api repos/DISTRIBUTION_REPOSITORY/git/ref/tags/vVERSION`. Require a lightweight commit tag equal to the accepted manifest `distribution_commit_sha`, and an owned draft or prerelease with the expected four assets: archive, appcast.xml, manifest.json and mistt.rb. A stable release, different tag target, missing asset or unexplained asset stops recovery for separate review.
2. Download those four assets with `gh release download vVERSION --repo DISTRIBUTION_REPOSITORY --dir FRESH_EXTERNAL_DIRECTORY`, selecting each expected filename with `--pattern`. Compare each downloaded file byte-for-byte with the preserved accepted artifact using `cmp`. Any mismatch stops recovery; do not overwrite remote assets. Recheck that `source_sha` is the independently reviewed landed revision and that the distribution commit remains on the public default branch.
3. Run `python3 release/release.py verify --directory FRESH_EXTERNAL_DIRECTORY` with the same protected Sparkle tool/key configuration. This rechecks archive hash/name, archive/feed signatures, embedded app identity/version/build/public key, nested code signatures, stapling and Gatekeeper without publishing. A failure stops recovery. Inspect the previous stable manifest and require a strictly increasing candidate build, as for normal publication.
4. If the verified release is still a draft, expose it as a prerelease using `gh release edit vVERSION --repo DISTRIBUTION_REPOSITORY --draft=false --prerelease=true --latest=false`. Keep the prior stable/latest release unchanged. Verify that its archive download works before changing the tap.
5. Read `gh api repos/sirerun/homebrew-tap/contents/Casks/mistt.rb` using the existing scoped tap credential. If its decoded content already equals the verified mistt.rb, no tap write is needed. Otherwise require it to equal the previous stable cask (or be absent on first publication), prepare a JSON body with the verified cask bytes base64-encoded and the freshly observed file SHA, and PUT that body using `gh api ... --method PUT --input BODY_FILE`. A concurrent-change rejection requires a fresh inspection, not a forced overwrite. Never put a private token in that body.
6. After the tap content and public archive URL/hash match the verified candidate, promote with `gh release edit vVERSION --repo DISTRIBUTION_REPOSITORY --prerelease=false --latest`. Check the latest signed appcast, release assets and tap again. If promotion fails, leave the verified prerelease/tap intact and repeat these inspections before retrying promotion. Automatic installed A-to-B update and safe-idle acceptance remain separate required checks.

The signed bundle leaves `SUEnableAutomaticChecks` unset so Sparkle can ask permission. The native delegate requests that permission on first launch when no prior response exists; the persisted response controls later launches. Automatic downloading/installing is the offered default, and the existing external disable switches still apply. See [Sparkle permission behavior](https://sparkle-project.org/documentation/custom-user-interfaces/).

Release builds and publication require `MISTT_RELEASE_SOURCE_SHA` set to the independently reviewed landed commit. Use a clean checkout at that exact SHA; tracked and untracked changes are rejected. The builder refreshes origin/main, requires reachability, freezes source before compilation and rechecks it after signing/notarization.
