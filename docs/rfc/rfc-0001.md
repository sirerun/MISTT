# RFC: MISTT — Microphone and App-Audio STT Streaming Service

- **Author:** sirerun
- **Status:** Draft — dual-source direction accepted; native capture and paired runtime qualification pending
- **Repository:** `github.com/sirerun/MISTT`
- **Created:** 2025
- **Revision:** 0.4 (2026-10-04 UTC)

---

## 1. Abstract

The current MVP captures **both microphone input and one explicitly configured app's playback output**, through native macOS APIs. Send them as separate timestamped streams to DGX, and label transcript events `microphone` or `call_audio`. One mute control closes both sources. Native per-app Core Audio taps replace the earlier mic-only capture boundary; the desktop still performs no ASR. See §5.6 for source/time/permission rules.

MISTT (**M**icrophone **I**nterface **S**peech **T**ranscription **T**ransport) is a thin desktop audio relay. It captures audio locally, sends it to **Microsoft VibeVoice ASR Streaming on the DGX**, and fans out transcription events to connected local gRPC clients. The desktop holds no speech model and performs no recognition, VAD, diarization, or model-specific chunking.

The entire desktop surface is a microphone toggle, an **On / Muted** label, and the **number of connected transcript clients**. Muting always wins over client demand. Capture occurs only when unmuted, at least one transcript client is connected, and the remote backend is ready. OpenRouter is a future backend extension, not an MVP fallback.

This RFC specifies the MVP contracts and implementation gates. The [bounded one-source DGX qualification](../qualification/vibevoice-streaming-asr.md) is landed. It does not qualify two simultaneous ASR contexts, real macOS capture, or a deployed production gateway.

## 2. Motivation

Existing speech-transcription tools often capture continuously or require every consumer to open its own microphone. MISTT provides one paired capture session for desktop assistants, automation, and other transcript consumers, with a visible user-controlled mute switch.

### Goals

1. Capture microphone input and the selected app’s playback as separate timestamped sources only while enabled, with subscriber demand and both sources ready; one mute stops both.
2. Keep the desktop lightweight: capture, transport, local client fan-out, and minimal state display.
3. Use `microsoft/VibeVoice` streaming ASR on the DGX as the sole production MVP backend.
4. Share one multiplexed remote session, containing two isolated recognition contexts, across all local transcript subscribers.
5. Keep backend-specific processing on the DGX and preserve an adapter boundary for future OpenRouter support.
6. Deliver native macOS 14.2+ capture and permission behavior first; Linux capture/packaging is deferred.

### Non-Goals (v0.1)

- Local speech models, Vosk, Google STT, or automatic cloud fallback.
- TTS, voice cloning, transcript editing/display, waveform displays, or a settings dashboard.
- Audio recording or transcript retention on disk.
- Per-client models/languages, raw-audio passthrough to transcript clients, Windows/Linux MVP support, global output capture, or automatic selection of another app.
- Echo cancellation, cross-source deduplication, speaker attribution, or isolating a single browser tab within an app tap.
- Unauthenticated remote access to the desktop relay.
- Transparent backend reconnection or unverified model-context rollover.

## 3. Terminology

| Term | Definition |
|---|---|
| **Desktop relay** | Local capture, mute authority, gRPC client hub, and thin outbound backend transport |
| **Transcript client** | An accepted local `StreamTranscription` subscription; the desktop UI is not one |
| **Session** | One bounded capture/remote-recognition run, with its own session ID |
| **DGX adapter** | Model-specific service managing VibeVoice audio conversion, streaming state, and transcript normalization |
| **On** | User has enabled capture; zero clients still means no capture |
| **Muted** | Capture is disabled by user action, startup default, or a failure |
| **Event** | A typed `StreamResponse` containing a lifecycle, transcript, or gap payload |

## 4. Architecture

```text
Native macOS app: [mic toggle] [On / Muted] [N clients connected]
  microphone input ─┐             │ status / paired control
  selected app tap ─┴─ timestamped PCM IPC ─► bundled Go relay
                                             ▲         │ authenticated TLS
                         local clients ─gRPC─┘         ▼
                                                DGX gateway
                                  microphone context │ call_audio context
                                       shared pinned VibeVoice weights
                                            Spark-managed workload

Future: another backend adapter may route to OpenRouter.
```

### 4.1 Ownership

- **Native app:** both OS permissions, per-app process resolution/private tap, microphone I/O, common host-clock timestamps, independent device conversion and bounded source queues, immediate paired gates and verified teardown. No ASR.
- **Go relay:** paired lifecycle/admission, binary capture IPC, bounded outbound transport, local client count and transcript fan-out. It opens no capture device and holds no model context. The headless CLI controls/subscribes through the native capture owner; without that owner, capture fails closed.
- **DGX:** authentication/admission, model loading/readiness, conversion from transport PCM to checkpoint format, chunk/lookahead buffering, model inference, per-source segment finality, capture-time mapping, backend limits, and sanitized errors.
- **UI:** observes authoritative relay state and issues an explicit desired mute value. Watching status does not subscribe to transcripts or activate the microphone. Closing the window does not implicitly unmute, start capture, or add a client; quitting the process stops capture.

### 4.2 VibeVoice Integration

Use **VibeVoice-ASR-Streaming**, with `microsoft/VibeVoice-ASR-Streaming-7B` as the checkpoint candidate identified by upstream deployment documentation. The installed VibeVoice TTS checkpoints are not substitutes for an ASR checkpoint. Pin the repository SHA, checkpoint revision, image digest, CUDA/PyTorch dependencies, and any remote model code before runtime qualification.

Upstream inspection at commit `1541f590c7099820f10ea012f48d2399282df69f` identifies live audio via `/v1/stream`, checkpoint geometry via `/v1/config`, and separate whole-file endpoints. The upstream live protocol consumes float32 little-endian mono PCM at the checkpoint's sample rate; its end marker flushes the remaining audio. Model-specific framing, conversion, and interpretation belong behind the DGX adapter, not in the desktop.

The adapter wraps a pinned upstream implementation. It exposes MISTT's normalized ready/audio/event/completion contract to the desktop. A transport connection alone is not readiness: readiness requires model-loaded status, validated audio capabilities, and successful admission of the recognition session. Do not use whole-file HTTP or output-token SSE as a replacement for a live microphone input stream.

Source references: [streaming ASR documentation](https://github.com/microsoft/VibeVoice/blob/1541f590c7099820f10ea012f48d2399282df69f/docs/vibevoice-asr-streaming.md), [vLLM deployment documentation](https://github.com/microsoft/VibeVoice/blob/1541f590c7099820f10ea012f48d2399282df69f/docs/vibevoice-vllm-asr-streaming.md), and [live server implementation](https://github.com/microsoft/VibeVoice/blob/1541f590c7099820f10ea012f48d2399282df69f/vllm_plugin/asr_streaming_server.py).

### 4.3 Data Flow

```text
microphone ─ native conversion + capture clock ─ independent bounded frames ─┐
app output ─ private tap + same capture clock ─ independent bounded frames ─┤
                                                                          ▼
   multiplexed authenticated transport → two DGX resamplers/ASR contexts
   → source-labeled lifecycle/transcript events → local subscriber buffers
```

One paired desktop session produces one multiplexed remote session with two independent recognition contexts, regardless of subscriber count. Pair admission reserves both contexts atomically; a one-source-ready response is insufficient. Only the DGX holds model context. No audio is captured during backend cold start, admission wait, or permission failure. The default proposed resource policy is on-demand loading with a 60 s idle unload, managed centrally through Spark; unloading must consider all active desktop sessions, not just one desktop's count. This policy remains subject to measured startup cost and shared-host admission.

## 5. API Contract

### 5.1 Local Proto (`proto/mistt/v1/mistt.proto`)

```protobuf
syntax = "proto3";
package mistt.v1;
option go_package = "github.com/sirerun/MISTT/gen/mistt/v1;misttv1";

service Mistt {
  rpc StreamTranscription(stream ClientMessage) returns (stream StreamResponse);
  rpc WatchStatus(WatchStatusRequest) returns (stream Status);
  rpc SetMuted(SetMutedRequest) returns (Status);
}

message ClientMessage {
  oneof kind {
    Config config = 1;
    KeepAlive keep_alive = 2;
  }
}
message Config {
  string language = 1;      // empty = configured backend default
  uint32 sample_rate = 2;   // 0 = default; otherwise must equal transport rate
}
message KeepAlive {}
message WatchStatusRequest {}
message SetMutedRequest { bool muted = 1; }
message Status {
  bool muted = 1;
  uint32 connected_clients = 2;
  bool capturing = 3;
  string reason = 4;        // user, no_clients, starting, backend_unavailable, etc.
  uint64 revision = 5;      // process-local monotonic status revision
}

message StreamResponse {
  string session_id = 1;
  uint64 sequence = 2;
  oneof payload {
    SessionStarted session_started = 3;
    TranscriptionEvent transcription = 4;
    SessionStopped session_stopped = 5;
    SessionGap session_gap = 6;
  }
}
message SourceFormat {
  string source = 1; // exactly "microphone" or "call_audio"
  uint32 sample_rate_hz = 2;
  uint32 channels = 3;
  string encoding = 4;
}

message SessionStarted {
  string backend = 1;
  string model = 2;
  string language = 3;
  uint32 sample_rate = 4;   // transport format, not checkpoint sample rate
  uint32 channels = 5;
  string encoding = 6;
  int64 capture_epoch_unix_ms = 7; // wall-clock correlation, not ordering
  repeated SourceFormat sources = 8;
  uint64 capture_epoch_host_ns = 9; // shared native host-clock origin
}
message TranscriptionEvent {
  string segment_id = 1;
  string text = 2;          // full current text of this segment, not append-only
  bool is_final = 3;
  double confidence = 4;   // -1 if unavailable; never fabricated from token scores
  uint64 start_sample = 5; // source-relative transport sample offset
  uint64 end_sample = 6;   // exclusive end; >= start_sample
  int64 wall_clock_unix_ms = 7; // capture wall-clock epoch + mapped source offset
  string source = 8;        // exactly microphone | call_audio
  uint64 start_offset_ns = 9; // shared capture epoch, mapped from source samples
  uint64 end_offset_ns = 10;  // exclusive; approximate model-window bounds
}
message SessionStopped {
  string reason = 1;       // muted, last_subscriber, max_duration, server_shutdown,
                           // capture_failure, backend_failure, drain_timeout
  int32 grpc_code = 2;     // canonical gRPC status number; 0 = OK
  string detail = 3;       // sanitized reason, no credentials or audio content
}
message SessionGap {
  uint64 start_sample = 1;
  uint64 end_sample = 2;
  string reason = 3;
  string source = 4;       // future source-specific discontinuity; MVP emits none
  uint64 start_offset_ns = 5;
  uint64 end_offset_ns = 6;
}
```

### 5.2 Subscription and Mute Semantics

1. **Initialization:** every subscription sends exactly one initial `config`, which may be empty. Validate it before acceptance; later request messages may only be `keep_alive`. Missing/repeated/invalid config fails with `INVALID_ARGUMENT`.
2. **Half-close:** request EOF after valid config leaves the response subscription active. Unsubscribe through RPC cancellation/deadline or transport closure. This follows [gRPC's independent stream directions](https://grpc.io/docs/what-is-grpc/core-concepts/).
3. **Client count:** accepted transcript subscriptions count once, including while muted or waiting for backend readiness. Rejected/pending-validation calls, UI status watchers, the DGX connection, and completed RPCs do not count. Disconnect/eviction decrements exactly once.
4. **Mute authority:** launch muted. `SetMuted(true)` closes paired forwarding/native capture gates immediately; existing clients remain subscribed. `SetMuted(false)` arms capture but never overrides zero clients, backend readiness, or OS permission. Repeated requests are idempotent and serialized. Late readiness callbacks cannot override a newer mute request.
5. **Config sharing:** the first accepted subscriber establishes session language. Explicit incompatible joins fail with `FAILED_PRECONDITION`; zero/empty values accept the established defaults. All clients use the server transport rate. Backend language support is validated before capture; unsupported configuration fails all affected waiting RPCs without opening either source.
6. **Session start:** with demand and user unmuted, establish a ready paired remote stream, then open both native sources. Transition `idle → starting → capturing`. The manager owns the pipeline context; disconnecting the first client does not cancel work for the remaining clients. Startup failure releases partial resources, ends affected subscriptions, and returns to muted/idle.
7. **Ordering:** each subscriber gets `SessionStarted` before transcripts/gaps. Late joiners get the existing session's original start envelope and future shared events only. No replay. Shared envelopes have strictly increasing session-wide sequences; repeating the start envelope for a late join is not a new shared event. Individual clients can observe jumps because they joined late.
8. **Transcript revisions:** the DGX adapter assigns stable segment IDs and increasing response sequences. Consumers replace the text of an unfinished segment on revision. A finalized segment is immutable. A VibeVoice chunk response is not automatically a finalized utterance; the adapter verifies which tail segment is still revisable and finalizes it only when safe or on successful drain. Timestamps map backend audio positions into the original capture timeline, not response arrival time; chunk-derived timestamps are approximate, not word-level accuracy claims.
9. **Slow consumers:** bounded per-client queues (default 64 events) never block capture or other consumers. Overflow evicts that client with `RESOURCE_EXHAUSTED`. The capture/outbound queue is also bounded; MVP overflow stops the session with `RESOURCE_EXHAUSTED`, rather than silently dropping audio and joining text across missing speech. `SessionGap` is reserved for future adapters with a verified discontinuity/reset contract; the MVP emits no recoverable gap.

`WatchStatus` sends an initial authoritative snapshot followed by changes. Status-only backpressure may coalesce snapshots to the latest state and cannot block capture. Every change increments the process-local revision; `SetMuted` returns the resulting snapshot. UI consumers use the newest revision within one relay connection and reset their revision tracking after reconnect, so a late control response cannot overwrite newer observed mute/count state.

### 5.3 Stop, Drain, and Failure

On mute, last-subscriber disconnect, duration expiry, or shutdown:

1. Serialize the transition to `stopping`, disable both source gates immediately, and stop the microphone I/O plus call tap I/O; release the private tap and aggregate device. No disconnect grace period delays closure of either source. Relay forwarding closes when the mute request is accepted; native gates close at their shared host-clock cutoff. `SetMuted(true)` acknowledges paired I/O closure, not completion of final drain. A bounded close failure is an explicit failure requiring forced owned-resource teardown; do not report successful closure while I/O remains active.
2. Quiesce both capture producers and close each source channel. Only already-captured frames may continue through the bounded drain; no new audio is sampled and no device is reopened.
3. The outbound adapter finishes each source’s queued audio and signals two distinct source EOF markers to the DGX. The DGX flushes each source's own VibeVoice tail/context and drains labeled final results; one overall deadline covers both. Keep the manager pipeline context alive during this phase; canceling the last subscriber must not preempt it.
4. Drain events before consuming terminal completion, bounded by `session.drain_timeout` (proposed default 5 s, to be qualified). Then close the remote stream and cancel remaining work. Timeout force-closes resources and reports `drain_timeout` / `DEADLINE_EXCEEDED` if no earlier failure exists.
5. Send `SessionStopped` on surviving response transports. Delivery is best-effort; a disconnected client cannot receive it. Muting retains accepted subscriptions in a waiting state; unmuting starts a new session ID after teardown completes. Other terminal causes end the subscriptions with the indicated gRPC status. A reconnect during teardown waits for a fresh session rather than aborting teardown.

Runtime capture/backend failures are explicit completion errors (§7.2), not indistinguishable channel closure. They immediately stop capture, set muted, preserve the first failure, deliver available safe final results if possible, then end current subscriptions. A subsequent user unmute and subscription may start a fresh session. A broken backend is not silently reconnected under the same session ID. Unexpected source/backend EOF before that source’s input EOF is a failure. Pair completion requires both successful source completions; one source final cannot finalize the other. Normal completion closes the current session, not the process.

### 5.4 Duration and Context Limits

`session.max_duration=0` disables only the operator's wall-clock cap. It does not disable backend audio-window, model-context, or resource limits. The DGX adapter negotiates capabilities before capture and enforces model limits before accepting an overflowing chunk. The desktop sends continuous transport frames and does not implement provider rollover.

A duration cap ends with `SessionStopped(reason=max_duration, grpc_code=0)` and OK; subscribers explicitly reconnect for another session. A backend audio/context limit ends with `backend_failure` and `RESOURCE_EXHAUSTED`. Finite window-based capture limits must reserve capacity for the final tail flush and lookahead; backend token-context limits can terminate sooner and are enforced server-side. Long-session acceptance tests must reach both kinds of limits. No indefinite VibeVoice-session promise is made before verified rollover exists.

Future rollover must verify capture timestamp continuity, ordering, overlap replay/deduplication, stable/final segment behavior, and speech crossing the boundary before it can be enabled. If a future Google backend is added, it must respect [Google v1's approximately five-minute streaming limit](https://docs.cloud.google.com/speech-to-text/docs/v1/quotas) through a conservative duration cap or verified rollover. Google is removed from the MVP milestone plan.

### 5.5 Error Codes

| Code | Condition |
|---|---|
| `INVALID_ARGUMENT` | Missing/repeated initial config or invalid transport audio parameters |
| `FAILED_PRECONDITION` | Incompatible client config, unsupported backend language/format, or either capture permission denied or call target invalid |
| `UNAVAILABLE` | Device unavailable, backend not ready/unreachable, or transport lost |
| `RESOURCE_EXHAUSTED` | Slow-client queue, capture/outbound overflow, backend admission/resource limit, or model context/window limit |
| `INTERNAL` | Unexpected runtime capture/backend failure |
| `DEADLINE_EXCEEDED` | Bounded startup or final-result drain expired |

`SessionStopped.grpc_code` matches the RPC's terminal status for terminal causes. A nonterminal user-mute stop uses OK but keeps the subscription open; disconnected clients receive no fabricated stop event. Backend errors are sanitized before reaching clients or UI.

### 5.6 Two Sources, Native Taps, and Capture Time

Every MVP session requires two independent streams labeled exactly `microphone` and `call_audio`. `call_audio` means capture provenance from the selected app, not speaker identity or guaranteed call-only content within that app. Clients receive both sources through one subscription; two streams do not double the connected-client count. Transcript segment IDs are namespaced by source, revisions/finality are independent per source, and the relay still assigns a strictly increasing session-wide event sequence. No cross-source concatenation or speech mixing is permitted.

The native macOS app owns both OS capture sources and permissions. Microphone input uses a native API with capture host-time metadata; the Go/malgo microphone-only path is superseded for this MVP. App playback uses an inclusion-only **private Core Audio process tap**, exposed through a private HAL aggregate device. The selected process continues normal playback (`muteBehavior = unmuted`); MISTT's Muted state stops capture, not the call app's sound. Never use a global tap, exclusion-list “all except” capture, or default-system-output fallback.

Minimum supported macOS is **14.2**. Configure the app bundle ID outside the minimal UI, resolve it to current HAL process objects, and validate process identity/incarnation at session admission. Only explicitly authorized app/helper process objects may be included. The first acceptance target is **TikTok LIVE Studio**, locally observed as version 1.36.4, bundle ID `com.tiktok.livestudio.desktop`. Installed helper identities are candidates, not an automatic allowlist: preflight must identify the actual audio-producing process and verify it belongs to the selected app. Acceptance uses local playback/preview without starting a public LIVE broadcast. Missing, ambiguous, exited or replaced targets stop the pair and return Muted; a later unmute resolves a fresh target/session. Silence alone is not target loss. Do not rely on `CATapDescription.bundleIDs` or process-restore APIs for the 14.2 baseline: the installed SDK marks those properties macOS 26-only. They may be used only behind availability guards without broadening scope or silently restoring capture.

Include `NSMicrophoneUsageDescription` and `NSAudioCaptureUsageDescription`. Microphone and system-audio recording grants are separate. Denial/revocation of either prevents paired recording. A tap-start permission prompt cannot lead to microphone-only transmission: hold/drop startup data until both source grants/readiness are confirmed. The native permission/capture spike must validate the actual prompt and gate behavior; no unverified permission-preflight API is assumed.

Timestamp each buffer from valid native capture `AudioTimeStamp.mHostTime` or equivalent Core Audio host ticks. Convert the epoch, buffer anchors and gate/stop cutoffs with `AudioConvertHostTimeToNanos` before storing/comparing any `_ns` field. Define `capture_epoch_host_ns = AudioConvertHostTimeToNanos(epoch_ticks)` and each offset as `AudioConvertHostTimeToNanos(buffer_host_ticks) - capture_epoch_host_ns`; raw host ticks are not nanoseconds. Transcript offsets use the resulting nanosecond map, and the wall-clock correlation refers to that same converted epoch. Reject missing/invalid host-time flags. Do not combine `mach_continuous_time` with a different Core Audio host-time epoch. Record a wall-clock correlation once for human-readable timestamps; NTP/wall-clock changes never alter source ordering. Each source has its own frame sequence and sample index, plus start offset in nanoseconds from the shared epoch. Initial offsets can differ; discard/trim startup buffers before the common gate-open epoch. Format conversion preserves the mapping, and the DGX retains it through model resampling/chunking. Transcript offsets use this map, never packet arrival/inference completion. Model lookahead/EOF padding adds no captured time; clip event ends to actual retained source samples. Model-window timestamps remain approximate, not word-level claims. Invalid/backwards timestamps, sample gaps/overlap, format/device changes, sleep/wake and source restarts fail explicitly; verified recovery/rollover is future work.

Native callbacks never block on sockets or inference. Use bounded per-source queues and a reserved-priority control path; overflow fails the pair rather than dropping or mixing audio. Each source has an independent resampler, audio/window buffer, model KV context, token/audio budget, segment state and EOF marker on DGX. Share pinned model weights and serialize inference fairly through a bounded scheduler. Start with one active pair per gateway, independent of local subscriber count; enforce aggregate context/queue caps, reserve the slot until actual in-flight inference cleanup, and qualify additional pairs before increasing that cap. Atomically admit/reserve the pair and report ready only after both contexts and transport limits are accepted. The existing one-stream inference proof establishes neither simultaneous-source latency nor memory/context headroom; qualify both before MVP acceptance.

Mute, zero clients, shutdown or failure stops **both** sources. Close native sample gates immediately at one host-clock cutoff, stop microphone/tap I/O and release app-owned tap/aggregate resources before draining. Trim or reject a buffer that straddles the cutoff; no post-cutoff sample can be forwarded. Retain only previously captured frames, send source-specific EOF, then deliver independent labeled finals within one overall drain deadline (initial proposal 5 seconds; remeasure for two contexts). Native app/relay loss also closes both via a validated ownership/watchdog path; no orphan capture survives. A source failure ends the pair, preserves the first failure and requires a fresh session plus explicit unmute. No implicit microphone-only fallback. Permission/tap/start/stop failure is never reported as successful paired capture or successful closure; bounded forced teardown and watchdog behavior need native acceptance.

See [capture ADR](../adr/0002-dual-source-native-capture.md) and [framing contract](../contracts/desktop-dgx-v1.md). Apple references: [process-tap guide](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps), [tap description](https://developer.apple.com/documentation/coreaudio/catapdescription), [host timestamps](https://developer.apple.com/documentation/coreaudiotypes/audiotimestamp), [host tick conversion](https://developer.apple.com/documentation/coreaudio/audioconverthosttimetonanos%28_%3A%29).

## 6. Configuration

YAML path via `--config`, flags, and `MISTT_*` environment overrides. Backend endpoint and credentials are provisioned outside the minimal UI; no backend picker is shown in the MVP.

```yaml
listen: "127.0.0.1:50051"
session:
  startup_timeout: 180s
  drain_timeout: 5s
  max_duration: 0s       # operator cap only; DGX limits still apply
capture:
  sources: [microphone, call_audio] # mandatory pair; no partial fallback
  call_audio:
    bundle_id: "com.tiktok.livestudio.desktop" # first acceptance target; operator-configurable
    include_helpers: []             # explicit validated identities only
  microphone:
    device: "default"
  sample_rate: 16000
  channels: 1
  format: s16le
stt:
  backend: dgx_vibevoice
  endpoint: "https://dgx.example.invalid/mistt"
  token_file: "/path/to/private/mistt-token"
  language: "en"
hub:
  client_buffer: 64
  audio_buffer_duration: 1s # independently bounded per source
log:
  level: info
```

- Bind only literal loopback addresses: `127.0.0.1:port` or `[::1]:port`. Reject wildcard, empty-host, hostname, and non-loopback listeners; v0.1 has no insecure network-listener override.
- Desktop transport is fixed at **16000 Hz, mono, signed 16-bit little-endian PCM**. Other values fail validation before either source is opened. The capture adapter owns device-native conversion/resampling and fails opening if it cannot produce that format. The DGX converts it to the checkpoint's advertised format; checkpoint sample rate/chunk/lookahead must never be guessed from older STT examples.
- Frames contain whole samples in immutable owned buffers, with source-relative contiguous sample offsets and shared capture-time offsets. Never expose reused OS callback buffers. Capture epoch plus offsets is the authoritative timestamp basis.
- Startup/drain timeouts and queue bounds must be positive; maximum duration must be nonnegative. `session.grace` is explicitly rejected as a retired unsafe key, not ignored with a warning.
- Verify HTTPS certificates; require a scoped backend credential. Provision token files with restricted permissions and never send/log them through UI state. The sample endpoint is a placeholder, not a recorded private DGX address.
- The DGX deployment separately configures model/checkpoint pinning, supported languages, session admission, context/window budgets, and global idle unload. The desktop cannot expand GPU allocations or load arbitrary client-selected models.

### 7.2 Core Interfaces

```go
// Shared internal/audio types.
type AudioFormat struct {
    SampleRateHz uint32
    Channels uint32
    Encoding string // s16le on desktop transport
}
type AudioFrame struct {
    Source string // microphone | call_audio, validated
    Sequence uint64 // independent, contiguous per source
    StartOffsetNS uint64 // captured host time relative to shared epoch
    PCM []byte // immutable owned buffer
    StartSample uint64
}

// Native capture produces two separate normalized timestamped sources over IPC.
type CaptureStream struct {
    Audio <-chan AudioFrame // bounded multiplex; independent per-source queues upstream
    Done <-chan error // pair completion, preserves first source failure
}
type Capturer interface {
    Open(ctx context.Context, cfg CaptureConfig) (CaptureStream, error)
    Close() error // idempotent; stop BOTH source gates/I/O, destroy owned tap/aggregate
}

// Backend is an outbound transport; recognition lives remotely.
type BackendStream struct {
    Events <-chan Event
    Done <-chan error
    Effective SessionConfig
}
type Backend interface {
    // Return only after remote session admission and format/config acceptance.
    // Each source EOF triggers its own final drain; ctx cancellation aborts both.
    Stream(ctx context.Context, audio <-chan AudioFrame, format AudioFormat, cfg SessionConfig) (BackendStream, error)
    Close() error // idempotent; releases stream and unblocks remaining work
}
type Manager struct { /* idle|starting|capturing|stopping; muted; subscriptions */ }
```

These are contract sketches, not implemented types. Each successful stream's `Done` channel is buffered with capacity one, sends exactly one terminal result (`nil` = normal completion; non-nil = failure), then closes. A failure during initialization returns synchronously after acquired resources are released. Closing the data channel means no more data; it does not report why the producer stopped.

Consumers drain data channels before consuming terminal completion. Completion must not discard buffered final events. The manager monitors capture completion independently from stalled backend consumption and can cancel a failed pipeline. Producers select on cancellation; `Close` must unblock them promptly. Session generation tags prevent stale completion/readiness callbacks from affecting a newer session. The manager owns pipeline cancellation and timers independently from individual RPC contexts.

### 7.3 Dependencies and Platform Boundary

- Desktop relay: `google.golang.org/grpc`, protobuf, native capture IPC behind interfaces, YAML, and `log/slog`.
- Native app: SwiftUI shell, native microphone capture and Core Audio process taps; no recognition SDK or Python/CUDA dependency on the desktop. Native capture API selection is qualified by the prototype, without adding UI controls.
- DGX: pinned Microsoft VibeVoice ASR Streaming, an ARM64/GB10-compatible inference image, and the normalization/auth gateway. Qualify upstream's reference inference path first; adopt vLLM only after its required plugin/build is demonstrated on this host.
- Code generation: `buf`, `protoc-gen-go`, `protoc-gen-go-grpc`.
- Backend work is scheduled through Spark manifests. Do not start model workloads with ad hoc SSH commands or assume upstream x86 image examples run on ARM64.

The local relay may require platform CGO/dynamic dependencies; the original unconditional single-static-binary claim is removed. Packaging must document the actual dependencies.

## 8. Desktop UI and Brand

The UI contains only:

1. One large microphone button, toggling one explicit mute state for **both** microphone and call playback capture.
2. One status label: **On** or **Muted**.
3. One count: **0 clients connected**, **1 client connected**, or **N clients connected**.

**On** means user-enabled, not unconditional sampling: with zero clients both sources remain closed. The relay exposes `capturing` separately for accessible description/tooltip truthfulness. Startup/connection/permission failures stop both sources and show **Muted**; a short sanitized reason is available through the same button's accessible description and tooltip, without an additional panel. No waveform, transcript, backend/model picker, recording timer, settings gear, or hidden audio-preview surface.

Use a recognizable microphone logo that doubles as the sole control. The muted state uses a visible slash and text, not color alone. A small calm color accent may distinguish enabled state; avoid continuous pulsing or volume animation. Support keyboard Space/Enter activation, clear focus indication, sufficient contrast, and an accessible toggle name/state. The count comes from the relay, not simulated UI state.

Logo variant **3** is selected: the microphone silhouette with two grille cutouts. Default enabled/muted assets are `assets/brand/logo.svg` and `assets/brand/logo-muted.svg`; the matching charcoal/amber mockup is the visual reference. Visual exploration and editable assets live in `docs/design/desktop-microphone.md` and `assets/brand/`. Logo selection does not change the API or privacy behavior.

## 9. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Two concurrent ASR contexts not yet qualified on GB10 ARM64 | Pin sources and dependencies; retain landed one-source proof; qualify paired memory, fairness, latency, limits and cleanup separately |
| Cold-start/shared GPU contention | No capture while waiting; bounded startup; central Spark admission; measured idle unload policy |
| Model context/window exhaustion | Server-side budgets including drain reserve; explicit terminal status; no unverified rollover |
| Slow network or model stalls | Bounded audio/event queues; fail explicitly on overflow; no disk spool |
| Final utterance lost on cancellation | Stop capture first, input EOF and bounded final drain, then pipeline cancellation |
| Client churn or late callbacks reopen microphone | Serialized transitions, session generation, exact refcounts, and mute precedence |
| Native tap permission, target/helper churn or teardown failure | 14.2+ process inclusion, separate consent, fail pair closed, bounded owned-resource teardown and native acceptance |
| Captured microphone contains speaker playback too | Labels identify capture provenance; use headphones for isolation acceptance; no unqualified echo cancellation/deduplication |
| Minimal UI hides backend problems | Fail to Muted and provide a concise accessible reason on the microphone control |

## 10. Alternatives Considered

- **Local Vosk or Whisper inference:** Adds model deployment and resource use to the desktop; replaced by the selected DGX backend for MVP.
- **A separate pair of captures per subscriber:** Duplicates device access and inference; one paired capture and one multiplexed remote session fan out results.
- **Browser-only WebSocket UI:** Not the requested desktop surface. WebSocket remains a backend transport option while local consumers retain typed gRPC.
- **Polling latest transcript:** Loses the live stream and segment revisions.
- **Whole-file ASR with streamed output tokens:** Does not accept live microphone input; not equivalent to streaming ASR.
- **OpenRouter now:** Deferred until the chosen provider supports the required audio-input behavior and explicit privacy/cost policy. Never a silent fallback.

## 11. Security & Privacy Considerations

1. **Consent and capture:** Launch muted; require both OS permissions and user-enabled paired capture plus subscriber demand and backend readiness. Stop both capture sources immediately on mute or last disconnect; no global tap or mic-only fallback. Drain may transmit only previously captured audio, within its timeout. Local subscription cannot override mute.
2. **Local access:** Loopback-only plaintext gRPC in v0.1. Local processes are trusted to subscribe and invoke controls; this is a documented boundary, not authenticated remote access. Future remote-client serving needs TLS/auth before non-loopback binds are allowed.
3. **Desktop-to-DGX:** TLS with certificate verification and a scoped credential. The authenticated gateway must prevent bypass to an unprotected upstream model/demo port. The example endpoint contains no private host details.
4. **Retention:** No app audio/transcript persistence, content logging, or offline replay. DGX buffers/model session state are ephemeral and cleared on completion; operational logs record IDs/state/errors without content or credentials. Future cloud retention/data transfer requires its own policy.
5. **Credentials:** Restricted token files, no credentials in UI status/logs, and no global credential reuse across unrelated DGX workloads.
6. **Model deployment:** Inspect and pin remote model code/dependencies; use scoped model/cache mounts. Existing broad workload mounts or privileged upstream examples are not blanket authorization for the MVP deployment.

## 12. Testing Strategy

| Layer | Required evidence |
|---|---|
| **Unit** | Muted startup, mute precedence, zero-client no-capture, exact refcounts, config conflicts, invalid loopback/PCM/grace config, stale callbacks, partial startup cleanup |
| **Integration** | Multiple subscribers share one paired capture/backend; start/revision/final/stop ordering; late joins/no replay; request half-close stays subscribed; reconnect during teardown gets a fresh session |
| **Stop & failure** | Capture closes before final drain; final tail survives input EOF; drain timeout terminates stalls; runtime capture/backend errors preserve the first failure; mute retains subscriptions; terminal failure closes them |
| **Audio** | Two independent PCM streams, contiguous per-source sequences/samples, shared host-clock offsets through resampling, format/drift/discontinuity rejection, cutoff-straddling buffers and bounded overflow |
| **Per-app tap** | TikTok LIVE Studio target/helper identity, two independent permission grant/deny paths, unrelated-app playback excluded, selected playback remains audible, target loss stops pair, no global/fallback capture |
| **Capture-free CI** | Fake paired native capture/IPC and remote backend fixtures; no microphone, system audio or GPU access; fixture mode cannot be selected in the production app |
| **DGX ASR** | Pinned ARM64 image/checkpoint on GB10 through Spark; paced concurrent distinct-source audio, text before each source EOF, independent final tail flush, stable segment revisions, supported-language tests, model limits, and complete session/resource cleanup |
| **Desktop UI** | Only microphone/state/count visible; actual count updates, zero/one/many grammar, keyboard toggle/focus, slash/text non-color distinction, failure-to-muted and accessibility descriptions |
| **Load** | 50 local subscribers to one remote session; slow-client eviction, bounded network backpressure, stable memory, and no head-of-line blocking |

Measure cold/warm readiness, chunk cadence, first-text and final-tail latency, real-time factor, memory, and behavior under shared-host contention. No subsecond latency or recognition-quality claim is accepted from an upstream demo alone. English is the initial fixture/acceptance language; expand the configured language set only after the selected checkpoint is verified for it.

## 13. Observability

- Logs: session IDs, client counts, both source gate/I/O open/close and tap ownership, mute transitions, backend readiness/failure, cap expiry, and drain timeout; no audio/transcript text.
- Metrics: active capture/session, connected subscribers, per-source audio queue depth/overflow and scheduler wait, consumer evictions, startup and transcript latency, session stops by reason, and backend resource/context errors.
- Local process health remains separate from backend readiness. UI state must use authoritative relay status rather than process-health inference.
- DGX health reports process/model readiness separately; no inference or microphone activation merely to answer a status watch.

## 16. Decisions and Remaining Gates

**Accepted direction:** use Microsoft VibeVoice streaming ASR on the DGX; keep the desktop a capture/transport client; reserve OpenRouter for later; show only microphone toggle, On/Muted, and connected-client count; implement all seven RFC review fixes; use logo variant 3; capture both mic and selected-app playback as separately timestamped `microphone`/`call_audio` streams, and stop both on mute.

**Proposed implementation defaults:** muted startup; loopback local clients; 16 kHz mono s16le transport per source; separate timestamped microphone/call_audio streams; no silent cloud fallback; English first; 5 s drain; on-demand model loading and 60 s global idle unload. These are design defaults, not claims about observed model behavior.

**Remaining implementation gates:** native microphone/per-app tap and two-permission preflight; TikTok audio/helper identity; framed IPC/proto/transport freeze; paired ASR inference/resource qualification; fair scheduling and long-session limits; paired cutoff/teardown and failure acceptance; selected UI; signed Homebrew release and installed auto-update evidence. No model deployment, code implementation, CI success, or release is implied by this RFC revision.
