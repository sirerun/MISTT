# MISTT paired desktop–DGX contract, draft v0.4

This pre-release contract replaces the one-source v0.3 candidate. It implements the source requirements in [RFC 0001](../rfc/rfc-0001.md) and the boundary in [ADR 0002](../adr/0002-dual-source-native-capture.md). The source/time rules are accepted; native permission/clock/teardown and paired-inference preflights must pass before implementation lanes freeze this draft. Existing one-source worker code is not accepted against this version. The owner subsequently authorized coding candidates against this draft while heavy builds and physical/model qualification are deferred; that authorization does not satisfy native preflight or runtime acceptance.

## Ownership and session identity

The signed native app owns microphone capture, the selected app's private Core Audio tap/aggregate, both permissions, conversion to transport PCM and host timestamps. The bundled Go relay owns local RPC subscriptions and transport, without device capture or ASR. DGX owns model conversion/inference. CLI subscriptions/control require the native owner; no alternate headless permission identity opens devices.

One UUID identifies a paired session and its generation. Every audio/control/event envelope carries this identity. Stale generations cannot start/stop a newer capture. Sources are exactly `microphone` and `call_audio`; subscribers receive both and count once. One remote connection admits the pair atomically. One loaded set of pinned VibeVoice weights serves two isolated recognition contexts, each with its own resampler, queue, sample sequence, audio/window/token budgets, transcript state and EOF. A bounded fair scheduler serializes GPU work; it cannot allow one active source to starve the other. Either source failure terminates the pair. Initial server policy is `max_active_pairs = 1`: three or more local subscribers still share that one pair. Reject a second pair before allocating context/queues with RESOURCE_EXHAUSTED. Enforce aggregate context/queue/worker bounds in addition to per-source limits; only raise the cap after measured concurrent-pair qualification. Disconnect keeps the slot occupied until in-flight inference actually finishes and both contexts/queues are released; idle unload cannot race that cleanup.

## Authenticated remote handshake

The DGX endpoint is a certificate-verified `wss` service configured outside the UI. Send the restricted token as a Bearer authorization header; never use a query-string credential. Keep the upstream demo private and inaccessible around gateway authorization.

Client JSON `start` declares `protocol: "mistt.paired.v1"`, `session_id`, language and exactly two source formats: 16000 Hz, mono, `s16le`. Gateway JSON `ready` echoes the accepted session/protocol/sources and supplies positive per-source frame/queue/audio/context caps, server `max_active_pairs` and aggregate admission limits, paired startup/drain policy and negotiated model identity. Ready requires both contexts, model readiness and paired resource admission. Unsupported protocol, missing/duplicate/unknown source, partial admission or language/format mismatch fails before native capture.

After ready, the native app opens both sources with forwarding gates closed. Permission/startup failure tears down the pair. Once both are usable it chooses one Core Audio host-clock epoch, opens the paired gates and sends `capture_started` with `session_id`, `capture_epoch_host_ns` and one `capture_epoch_unix_ms` correlation. Go forwards this metadata before any binary audio and emits the local `SessionStarted` envelope. Startup audio needed to trigger system permission is discarded. Trim/drop any initial buffer portion before the common gate-open epoch; first forwarded offsets cannot be negative. No source is transmitted before both are ready.

## Binary audio framing

Each WebSocket binary message contains exactly one source frame. The same frame body crosses native-to-Go IPC; Go does not combine or re-time sources. Header integers use big-endian/network order; PCM samples use signed little-endian 16-bit. Header size is 52 bytes.

| Byte offset | Size | Field |
|---|---|---|
| 0 | 4 | ASCII `MST1` magic |
| 4 | 16 | Session UUID bytes, RFC 4122/network byte order |
| 20 | 1 | Source ID: 1 = `microphone`, 2 = `call_audio` |
| 21 | 3 | Reserved, all zero |
| 24 | 8 | `source_sequence`, contiguous per source, begins at 1 |
| 32 | 8 | `start_sample`, source-relative normalized 16 kHz index, begins at 0 |
| 40 | 8 | `capture_offset_ns`, buffer start relative to shared capture epoch |
| 48 | 4 | `sample_count`, positive, at most 1600 (100 ms) |
| 52 | 2 × sample_count | Mono `s16le` PCM, exact length |

Native callbacks can have different sizes; independent conversion/framing produces frames no longer than 100 ms, including short tail frames. Each source starts at its own capture offset, which need not be zero. Zero-length audio, unknown source, wrong generation, duplicate/gapped sample sequence, nonzero reserved bytes, inconsistent length, backwards time or a verified clock discontinuity fails the pair. Queues are separately bounded (initial proposal: one second/source). Aggregate transport/control buffers are also bounded; no disk spool or silent audio drop. Cross-language golden frames must verify UUID byte order, header bounds, sample counts and PCM endianness. [Synthetic frame/clock vectors](fixtures/paired-v1.json) define both sources, framed IPC lengths and a non-unit host clock; they are codec fixtures, not capture evidence. [Negative/boundary vectors](fixtures/paired-v1-negative.json) cover malformed frames, per-source ledgers, clock scale and exclusive sample-instant cutoff; codec-conformance cases are distinguished from wire-validation failures.

Timestamp buffers using valid native input/tap `AudioTimeStamp.mHostTime` or equivalent Core Audio host ticks. **Convert ticks with `AudioConvertHostTimeToNanos`**: `capture_epoch_host_ns = AudioConvertHostTimeToNanos(epoch_ticks)` and `capture_offset_ns = AudioConvertHostTimeToNanos(buffer_host_ticks) - capture_epoch_host_ns`. Convert gate-open/stop cutoffs and every anchor with the same function before comparisons; raw ticks must never populate `_ns` fields. Transcript offsets are mapped nanoseconds from that epoch; derive the one wall-clock correlation from the same converted epoch. Require valid host-time flags and reject negative/invalid anchors. Golden clock fixtures must include a non-unit ticks-to-nanoseconds scale. Do not substitute packet receipt time or mix a `mach_continuous_time` epoch. Preserve frame anchors through each native and model resampler; map transcript sample positions through those anchors to the shared epoch. Source sample counters remain independent. Wall clock is descriptive; its later changes do not change ordering. Clock drift tolerance and format/device/sleep discontinuity detection are measured in native preflight; no unqualified assumption of two devices running at identical rates. Unknown or invalid native timestamp metadata fails closed.

## Transcript and completion events

Gateway transcript JSON includes `session_id`, `source`, increasing `source_event_sequence`, source-namespaced `segment_id`, full current `text`, `is_final`, `confidence` (-1 if unavailable), source-relative `start_sample`/`end_sample` and mapped `start_offset_ns`/`end_offset_ns`. The local proto carries the source/time fields and Go assigns a strictly increasing session-wide response sequence. Capture offsets allow clients to compare sources despite inference arrival order; no global chronological emission guarantee. Model lookahead/EOF padding never advances the captured timeline; clip reported segment ends to that source’s actual retained samples. A finalized segment is immutable. Labels indicate capture provenance, not speaker identity or echo-free speech.

After capture stops, send JSON `source_end` separately for each source, containing session/source, last sequence and total transmitted sample count, plus `cutoff_offset_ns` (the confirmed native cutoff_host_ns minus capture_epoch_host_ns, checked nonnegative uint64, identical for both sources). Gateway verifies all received sample instants are strictly before this cutoff and fails the pair on conflicting cutoffs or invalid retained ledgers; it never fabricates successful finals. Native-to-Go source_end keeps its original fields; Go attaches the cutoff only after verified paired closure. (last_sequence and total_samples are both zero if and only if that source transmitted no frames). EOF follows all retained frames for that source. DGX flushes its own partial window/context, emits safe labeled finals and `source_done` with that source's success/failure. Only two successful `source_done` markers permit overall `done`; premature close, a missing source or source failure terminates the pair explicitly. Do not fabricate finality on timeout/failure. Keep draining event queues before consuming completion.

Mute/last disconnect/shutdown closes both native gates at one host-clock cutoff, stops both I/O sources and destroys owned tap/aggregate resources before final drain. Cutoff applies to sample timestamps, not a sample’s nominal duration: retain a normalized 16 kHz sample only when `capture_epoch_host_ns + capture_offset_ns + i * 62500 < cutoff_host_ns` for its zero-based frame index `i`. Native trims before framing; Go rejects any retained sample timestamp at/after cutoff without rewriting sequence/sample ledgers. A final sample timestamp before cutoff is valid even when its nominal 62500 ns duration extends beyond it; never emit a zero-sample frame. Use checked integer arithmetic. Apply the same sample-instant rule at the native source rate before conversion, preserve converted anchors and clip resampler output at the normalized cutoff. Relay mute processing pauses live DGX audio forwarding while requesting native stop, but its independent IPC reader continues into bounded per-source queues. After a verified cutoff ACK, only validated retained pre-cutoff frames drain. If closure is unconfirmed, abort the remote pair and discard queues with an explicit failure, without fabricated finals. Native stop acknowledgment names the generation/cutoff and confirms both I/O closures. `SetMuted(true)` waits for this acknowledgment or reports bounded closure failure; it does not wait for model drain. Forced teardown/watchdog behavior must be qualified before any success claim. Native or relay death must not leave orphan capture.

Initial startup proposal is 180 seconds (single-source cached load was approximately 125 seconds); initial overall drain proposal is 5 seconds for both sources. Requalify both under paired inference. Final drain does not reopen a source, and neither deadline overrides immediate gates. Preserve the first failure, set Muted, terminate affected subscriptions and require explicit unmute with a fresh UUID. No automatic partial-source fallback or reconnection under the old ID.

## Native–Go IPC

Launch only the app-owned bundled relay via structured arguments; no shell or selectable fixture executable in production. Native writes framed messages to child stdin: four-byte big-endian length counting the following kind byte plus payload, then one-byte kind followed by the payload. A control message is at most 65537 bytes after the prefix; an audio message at most 3253. Kind 1 = bounded UTF-8 JSON control (at most 64 KiB); kind 2 = the binary source frame above (at most 3252 bytes). Reject invalid lengths/kinds before allocation. Native controls include `capture_started`, source end and failure; generation-specific controls carry session identity and solicited responses carry the original request ID. Process-wide controls use their own sequence/revision identity.

Relay stdout is bounded JSON lines for authoritative status and `capture_start`/`capture_stop` requests with request ID, generation and validated target/config. It contains no audio, transcript content or credentials. Status snapshots may coalesce; control requests may not. Reserve control capacity and prioritize stop/ack over audio backlog. The native mute button closes its own gates before awaiting child IPC; RPC-initiated mute requests receive the same paired stop path. Reader/writer stalls, EOF, child death, stale requests and acknowledgment loss have bounded fail-closed behavior. Native capture ownership is single-instance and independent of any subscriber's RPC lifetime. Freeze exact stop/watchdog deadlines after T2.0's measured prototype.

### Typed IPC controls and correlation

`session_id` is the UUID generation; there is no additional JSON `generation` field. `request_id` is a fresh UUID per control operation, independent of the session UUID. Unknown types/fields, malformed identities, invalid values or reused request IDs with different payloads fail closed. JSON counters/timestamps decode as exact integers into typed 64-bit fields, never floating point. Child stdout lines and control payloads are bounded; no secrets/audio/transcripts.

| Direction | `type` | Required fields beyond type |
|---|---|---|
| Go → native | `capture_start` | request_id, session_id, sources, microphone:{device}, call_audio:{bundle_id,include_helpers,include_helper_executables?} |
| Native → Go | `capture_started` | matching request_id/session_id, capture_epoch_host_ns, capture_epoch_unix_ms, exactly two source formats, microphone_ready=true, call_audio_ready=true |
| Go → native | `capture_stop` | request_id, session_id, reason |
| Native → Go | `capture_stopped` | matching request_id/session_id, cutoff_host_ns, microphone_io_stopped=true, tap_io_stopped=true, tap_destroyed=true, aggregate_destroyed=true |
| Native → Go | `capture_failed` | session_id, request_id if failure answers a request (mandatory then), sanitized code/detail, closure_confirmed boolean; not a stop ACK |
| Native → Go | `source_end` | session_id, source, last_sequence, total_samples |
| Native → Go | `native_set_muted` | request_id, command_sequence, expected_status_revision, muted boolean; process-wide authority, not an audio generation |
| Go → native | `control_result` | matching request_id, status and error fields (each nullable, at least one non-null); stale_command/status_conflict require both current status and error; a successful mute result requires paired closure |
| Go → native | `status` | muted, capturing, connected_clients, reason, revision |
| Go → native | `heartbeat` | monotonically increasing exact counter; no capture authority |

The [typed JSON schema and examples](native-control-v1.schema.json) define exact field names/types/bounds. Source-format arrays use canonical microphone then call_audio order; packets/events remain independently interleaved. Source formats are the same named 16000 Hz/mono/s16le pair as the remote handshake. Target requests name only the externally configured app/helper identities; native independently resolves their live HAL objects/incarnations. A target format/identity mismatch is a start failure. Start succeeds only after both usable sources and gates are open, with pre-epoch/startup data discarded. Do not start twice on duplicate requests or partially reuse a source.

Duplicate identical request IDs return the cached in-generation result without rerunning I/O. Duplicate stop of an already closed current session returns its actual recorded cutoff/closure flags using the caller's request ID. A stop for an old/unknown session never touches a newer session: return a sanitized stale-session failure instead of claiming closure. Ignore stale unsolicited completions for lifecycle purposes; a pending request must resolve as stale/failure or time out. Generation-specific response caches are bounded and cleared on session retirement. Process-wide native UI command high-water marks survive session retirement; a bounded cache may replay an identical command result, but evicted old commands remain stale and cannot reapply. Each UI command has strictly increasing command_sequence plus expected_status_revision; stale sequence or revision returns explicit conflict/current status without changing relay desired state. Return `control_result` with both the current nested status snapshot and an error whose code is `stale_command` or `status_conflict`; do not depend on a separate status line for correlation. A successful result has status and null error; other failures have null status and a sanitized error. An identical cached retry replays its original snapshot/result, which may have an older revision; native must never replace a newer UI snapshot with that older revision. Require a new user intent with a new sequence/current revision to retry; no automatic stale unmute retry.

`native_set_muted(true)` closes local native gates immediately, then invokes the relay's same serialized mute path. The relay still issues/receives a correlated `capture_stop`/`capture_stopped` so RPC/UI results confirm closure; the native side may answer from the just-completed recorded stop. `native_set_muted(false)` only arms demand/readiness checks; it cannot itself start a device or override a newer mute. On startup the native desired state is Muted. API-initiated unmute/start obeys the same authoritative relay revision; stale status/control results cannot reopen gates.

`capture_failed` is never a stop ACK. After capture_started, a runtime failure triggers a correlated capture_stop/capture_stopped before closure can be confirmed; overall outcome remains failed even if safe partial results drain. Before gates ever opened, failed start has no captured data to drain. A stale-stop failure echoes its request_id, names the stale session and sets closure_confirmed=false without changing the active session.

Stop ACK confirms gate cutoff and actual paired I/O/resource teardown, **not** delivery of queued audio or source EOF. ACK/control can bypass unsent PCM backlog; source_end has a per-source barrier behind all retained PCM of that source, even when control is prioritized. Its last_sequence/total_samples describe post-trim audio actually transmitted; Go cross-checks cutoff/sequence/sample ledgers and rejects violations without silently rewriting them. An EOF may pass the other source only after its own audio writer barrier completes. Native’s single writer serializes complete IPC frames; control priority applies only to unstarted frames and cannot preempt an in-progress OS write. Nonblocking/deadline-bounded writes must finish a partial frame or declare the IPC stream failed; never interleave frames. Write failure triggers independent local paired teardown without waiting on the pipe; Go treats lost ACK as closure-unconfirmed. Callbacks never write pipes or block on its queue. Native gate stop cannot wait on writer/backpressure. Go's remote/event reader likewise cannot block the separate stdout control writer.

Numeric stop/watchdog budgets remain preflight proposals until measured: `stop_ack_timeout = 1s`, heartbeat every `500ms`, native heartbeat-loss cutoff after `2s`. Observe process/pipe death immediately where available instead of waiting for heartbeat timeout. Stop ACK timeout is closure-unconfirmed failure (no success); native owns a bounded forced teardown/termination path if its I/O cannot be stopped. A native owner crash releases its OS resources and the relay fails closed on input EOF; relay loss triggers the native stop/watchdog. T2.0 must prove both paths and either validate or revise these values before contract freeze. Startup/drain limits remain independently negotiated; heartbeat never resets those deadlines.

## Target and acceptance

First target: installed TikTok LIVE Studio, observed version 1.36.4, bundle ID `com.tiktok.livestudio.desktop`. Resolve inclusion-only HAL process IDs on macOS 14.2+, validating current process incarnation and app ownership. Identify any actual audio-producing helper before explicitly including its identity; installed helpers alone are insufficient. No global/exclusion tap, browser substitution, default output fallback or automatic target restore. Missing/ambiguous target, process exit/replacement or denied/revoked permission stops the pair. Silence is valid. Keep the target audible with `muteBehavior = unmuted`.

The selected owner app need not itself have a HAL process object. Resolve its unique live main process from the configured bundle identity, then resolve only explicitly configured audio producers. Local test-tone playback identified TikTok's bundleless `MediaSDK_Server` as an active HAL output producer; that inventory correlation does not prove captured signal or exclusion. For this MVP, optional `include_helper_executables` defaults to `[]` and accepts only `Contents/Resources/app/electron/sdk/lib/MediaSDK_Server` under owner `com.tiktok.livestudio.desktop`. The native qualification allowlist fixes helper signing identifier `MediaSDK_Server` and owner/helper team `MJ797D8U6F`; a path-only match cannot authorize capture. Validate both live code signatures, exact canonical executable path inside the owner's bundle, same user, direct parent PID, owner/helper process-start fingerprints and current PID-to-HAL mapping. Revalidate immediately before start and during capture. Any mismatch, owner/helper replacement or loss fails the pair closed. Tap only the explicitly resolved producer object; never include all descendants or substitute an idle helper. Additional executable helpers require a new qualified allowlist entry, not an arbitrary path supplied by a client.

Acceptance must include distinguishable simultaneous microphone/TikTok playback, unrelated-app exclusion, source/time isolation through jitter/resampling, permission failures, both source tails, cutoff-straddling buffers, app/helper loss, IPC death/stall and three actual subscribers counted as three. Local TikTok playback/preview is sufficient; this task does not authorize a public LIVE broadcast. Existing single-source synthetic inference proof is retained as a prerequisite, not dual-source acceptance.

Coordinator owns shared contracts and evidence. Go worker owns proto/relay/IPC; DGX worker owns gateway and paired inference; Apple worker owns native capture, permissions and minimal UI. Each uses an isolated external-SSD worktree. Resume lanes only after updated contract preflight; this planning pass does not execute new capture implementation.

## Update admission extension (coding candidate)

Status (including nested control-result status and local RPC) adds required booleans `update_ready` and `update_reserved`. Ready means Muted, no starting/active/draining backend pair and confirmed native source/resource closure; unknown closure is never ready. Native sends `native_prepare_update` or `native_cancel_update` with request_id, command_sequence and expected_status_revision, using the same exact identity, replay/high-water and conflict semantics as native_set_muted. The correlated control_result carries current status. Prepare atomically reserves an already-ready pair; busy/unknown closure returns an explicit failure and never mutes to become ready. Reservation blocks native/remote unmute and fresh capture until correlated cancel or shutdown. Cancel only releases the reservation and never unmutes. Native additionally checks its own Core Audio state before installation. Relay loss or stale status invalidates readiness. Update installation/relaunch starts only after a positive correlated prepare result and current local/relay reservation readiness; downloads/checks may occur earlier.

### Exact remote readiness and completion keys

Remote `ready` requires `type`, `protocol`, `session_id`, `language`, `model`, canonical `sources`, `max_active_pairs`, `aggregate_max_audio_samples`, `aggregate_max_queue_frames`, `aggregate_max_context_tokens`, `max_inference_workers` (1), `startup_timeout_ms`, `drain_timeout_ms`, `aggregate_drain_reserve_model_samples` and `aggregate_drain_reserve_tokens`. The `model` field is an exact object with `id`, `revision`, `source_commit`, `sample_rate`, `chunk_samples`, and `lookahead_samples`. The first three identify the pinned production model/source; geometry values are exact positive bounded integers. The local protobuf model label is `id@revision`, derived only after validating this object. Each source entry has `source`, `sample_rate_hz`, `channels`, `encoding`, `max_frame_samples` (at most1600), `max_queue_frames`, `max_audio_samples`, `max_context_tokens`, `drain_reserve_model_samples`, `drain_reserve_tokens`. Caps/deadlines are bounded positive exact integers, reserves nonnegative and within caps; booleans are not integers. Advertised policy is configured, not proof of measured capacity. Reject unknown/missing keys, unsupported formats, excessive allocations and partial readiness.

Remote `source_done` has exactly `type`, `session_id`, `source`, `success`, `code`, `detail`; a success is true with null code/detail. Failed pairs terminate as transport failure without fabricated successful finals/completion. Remote `done` has exactly type/session_id and is valid only after both successful source markers and all event queues are drained. No unnegotiated error JSON message is accepted; sanitize bounded WebSocket/handshake failures into explicit local failures.
